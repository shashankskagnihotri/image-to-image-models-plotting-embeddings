LATENT PCA TRAJECTORIES: REPRODUCIBLE IMAGE-EDITING EXPERIMENT
=============================================================

GOAL
----
Run an editor twice: original image versus the same image with Poisson shot
noise, using the same prompt, model, scheduler settings, and random seed.
Record every spatial latent vector before step 1 and after every denoising
update. Fit one PCA on the original image's step-0 spatial vectors ONLY.
Project both complete trajectories with exactly this same PCA basis.
Produce PDF plots, an animated GIF, and the raw latent tensors.

WHAT EACH POINT MEANS (CRITICAL FOR CORRECT INTERPRETATION)
-----------------------------------------------------------
Latents x_s have dimensions [C,H,W]. For every spatial grid location (y,x),
take its entire C-dimensional vector x_s[:,y,x] as ONE PCA observation.
This yields H*W observations at each step. DO NOT fit PCA on an image mean,
channel mean, flatten-whole-image vector, or on all denoising states together.
PCA is fitted only on ORIGINAL image's x_0 spatial vectors. PC1/PC2 stay
fixed for both images and all steps. Every plotted point is a complete
C-dimensional latent vector projected into two dimensions.

"State 0" means the initial noisy state BEFORE the first denoising step.
It does NOT mean diffusion time t=0 (often the terminal clean state).
"State k" for k>0 means AFTER the k-th scheduler update. The callback API
only exposes end-of-step latents, which is why run_experiment.py captures
the initial state directly inside prepare_latents, and all later states via
the callback. We do not modify scheduler, model weights, or guidance rules.

MODEL-SPECIFIC MEANING
----------------------
InstructPix2Pix is NOT a flow-matching model. It is a diffusion editor:
  - Denoising x_0 starts from seeded Gaussian noise, independent of image.
  - Image VAE latents separately CONDITION the denoiser at each step.
  - The two x_0 states should be identical under the paired seed; this is
    expected and is NOT evidence that the protection has no effect.
  - 'conditioning_image_latents' records the image condition separately.
  - The model source does not apply VAE scaling to its image-condition
    tensors, so do not confuse that distribution with denoising states.

SD3.5 is a flow-matching model running the image-to-image pipeline:
  - Image VAE posterior MODE is used so encoding itself adds no randomness.
  - The image latents are scaled/shifted exactly as SD3 expects and fed to
    the official image-to-image pipeline as pre-encoded latent input.
  - The pipeline mixes them with Gaussian noise via its standard scheduler.
  - The generator is RESET to the identical seed for the second image, so
    the Gaussian noise draw is shared. The image content may differ at x_0.
  - Strength determines the denoising-start location. With strength=0.75,
    28 requested steps need not give 28 actual denoising updates.

The points are VAE/denoising latent vectors, NOT transformer hidden states,
text embeddings, attention vectors, or predicted velocity vectors. Their
spatial positions are matched between runs, so we may plot each position's
path. These coordinates are not literal physical flow particles; changing
image content spatially can make coordinate-wise matching semantically
imperfect. PC1/PC2 may preserve limited variance; see pca_basis.npz and
the full-channel distance metrics before claiming a protection mechanism.

NOTE ON SCIENTIFIC INFERENCE
----------------------------
Poisson shot noise is merely an illustrative perturbation; it is not proven
to stop image editing. A single image and a single seed cannot establish
robustness. For publication, replicate across images, perturbation levels,
seeds, edit prompts, and strengths; summarize effect sizes across trials.

TESTING NOTE
------------
The sample generation and the plotting/PDF/GIF path were verified without
loading a full diffusion model in the packaging environment. That
environment lacks torch, diffusers, and a GPU. Real model inference is
therefore intentionally delegated to Cursor on your GPU, as requested.
Do not describe these sample/plot checks as a real model-inference test.
